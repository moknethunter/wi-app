# Wi-Call Activation Server — V6.0

رقم القرار WICALL-SPEC-006. هذه إضافة ملزمة إلى WICALL-SPEC-005 (V5.0) بكامل أبوابها ومتطلباتها واختبارات T01–T90؛ تستبدل قرارات البنية والتنفيذ المتعارضة فقط. لا تلغي الوظائف أو تخفف اختبارات القبول. نطاق المنتج الحالي: تطبيق تفعيل واتصال مستقل واحد، com.mokasas.wikall، في wi-app. تطبيق المستخدم الثاني مشروع مستقل لاحقاً يتوافق عبر البروتوكولات، لا عبر أكواد مشتركة.

## 1. ثوابت المنتج
- Android 10+ غير مروّت، لا su أو CAP_NET_ADMIN أو iptables أو ADB في الإنتاج، ولا تطبيق VPN أو EasyTier خارجي.
- Local-only: لا إنترنت ولا بيانات هاتف ولا STUN/TURN أو ترحيل خارجي. صلاحية INTERNET للمقابس المحلية فقط. النقل المستقبلي معطل افتراضياً.
- سلطة التفعيل شبه رئيسية إدارياً: تخصيص الرقم، توقيع العضوية، التجديد والإلغاء، تفويضات الربط. ليست شرطاً دائماً للاتصال بين العقد المصرح بها.
- التفعيل والاتصال الصوتي والرسائل داخل APK واحد. هوية ثابتة آمنة، عنوان تراكبي ديناميكي، اكتشاف تلقائي، إعلان موثق، ربط وترحيل متعدد القفزات، دمج مصرح، تنقل واستعادة. لا جسر لحظي دون وصلة فيزيائية فعلية.
- حماية مفاتيح Keystore، مصادقة متبادلة، حماية replay، رسائل مشفرة، حماية بيانات المستخدمين، رفض الشبكات غير الموثوقة.
- اختبار ميداني على أجهزة غير مروّتة شرط القبول؛ المحاكي لا يثبت الجسور أو الصوت الميداني.

## 2. البنية
Modular Monolith + Clean Architecture + Ports and Adapters + أحداث محددة النوع. فصل domain/application عن Android وJNI وRoom والواجهات. الاعتماد من adapters نحو منافذ المجال؛ لا اعتماد دائري ولا global mutable singleton بلا مالك لدورة الحياة. DI عبر Hilt عند حدود التركيب. تقسيم وحدات Gradle عند وجود فائدة قابلة للقياس، لا إنشاء طبقات فارغة.

المسؤوليات: identity/security/configuration؛ activation؛ orchestration/physical links/discovery/overlay/vpn/bridge/relay/routing/merge/mobility/health؛ edge server/directory/presence/election؛ calls/media/messaging/recovery؛ integration gateway؛ storage؛ diagnostics؛ UI. لكل مكون واجهة صغيرة ومالك حالة واختبارات. الأحداث المحلية لا تحمل أسراراً، وتعالج التكرار وإلغاء العمليات والتزامن. لا تستعمل EventBus لتجاوز التحقق أو المعاملات.

## 3. منافذ المكونات
OverlayEngine بداية موجودة، يُنقل نموذج إعداد المحرك لاحقاً من TOML إلى نموذج domain محايد، وتُنقل DTOs بعيداً عن نوع EasyTier. التنفيذ EasyTierAdapter مسؤول عن JNI وRust والتحقق. VoiceEngine لعقد الصوت والإشارات مع WebRTCAdapter؛ MembershipRepository وDirectoryRepository وMessageRepository بدلاً من منفذ قاعدة بيانات عام؛ PhysicalLinkProvider وSocketTransport لمنصة Android؛ IntegrationPort للاتصال بالسيرفرات. لا تنفذ منفذاً جديداً إلا مع محول حقيقي واختبار وموضع استخدام. إيقاف وعزل كل خدمة وتحرير مواردها، وإعادة المحاولة المحدودة عند الخطأ.

## 4. التكامل
IntegrationGateway وحد مستقل له سجل موصلات معتمدة وقدرات معلنة، إصدارات بروتوكول، تفاوض قدرات، أخطاء محددة، مصادقة وتفويض خاصان بكل سيرفر، حدود معدل وحجم ومهلة وإلغاء، معرفات معاملات ومنع تكرار، فحص توافق، سجل تدقيق دون أسرار. رفض الإصدار غير المتوافق دون إفساد الجلسات السابقة. الأسرار محمية ولا تستقبل من الإعلان العام.
الأولوية: بروتوكولات Wi-Call للتفعيل والدليل والإشارات والرسائل والإلغاء والدمج، ثم التكامل المحلي مع سيرفرات موثوقة أخرى. REST/WebSocket، SIP مع Asterisk أو FreeSWITCH، EasyTier، WireGuard، MQTT أو موصلات AI أمثلة مستقبلية مشروطة بعقود وقدرات حقيقية وليست ميزات حالية. WireGuard ليس بديلاً مكافئاً لشبكة mesh. لا ينشأ اتصال خارجي دون سياسة صريحة في إصدار مستقبلي.

## 5. التطوير والصيانة
اعتماد feature flags محلية افتراضياً معطلة للميزات غير المكتملة، لا تحميل شيفرة خارجية غير موثوقة. الإصدارات الجديدة تحافظ على معرف التطبيق والتوقيع وترحيلات Room والمفاتيح والعضويات والسجلات. اختبارات توافق العقود مع إصدارات البروتوكول السابقة، وخطة ترحيل موثقة. لا تعديلات مدمرة بلا نسخة احتياطية مناسبة. الوثائق README بالإنجليزية وأدلة التشغيل والتطوير بالعربية؛ شرح المجلدات والملفات والكلاسات والدوال الأساسية، ADR، مخطط الاعتماديات، سياسة الترقيات، سجل التغييرات، دليل الأعطال. ترخيص EasyTier ومصدر التعديلات عند التوزيع.

## 6. بوابات الجودة
اختبارات وحدة وتكامل وعقود وبنية وعدم انحدار وأمان وأداء وتوافق وend-to-end. Architecture tests تمنع الاعتماد الدائري وتجاوز المنافذ. تُحفظ اختبارات T01–T90 ولا تخفف. A01: UI لا تستدعي JNI أو DAO مباشرة. A02: المجال لا يعتمد Android أو SDK خارجي. A03: إضافة محول لا تتطلب تعديل منطق التفعيل. A04: تعطيل موصل لا يعطل الوظائف المحلية. A05: رفض عقد غير متوافق. A06: فشل الموصل مع استعادة محدودة. A07: عدم تسرب الأسرار أو حركة الإنترنت. A08: الحفاظ على البيانات عند ترقية الإصدار. A09: لا root ولا صلاحيات استثنائية. A10: تحقق آلي من حدود الاعتماد. هذه متطلبات قبول جديدة، لا ادعاء باجتيازها.

## 8. سياسة إعادة البناء
فرع development/v6-architecture-rebuild مبني على أحدث إصلاح PR6 لكي لا تضيع التعديلات. إعادة الهيكلة تدريجية لا إعادة كتابة عمياء. إعادة استخدام التفعيل والشهادات وQR وKeystore وWebRTC وRoom والرسائل والاختبارات بعد التحقق. تفكيك ConnectionController وفق المسؤوليات ونقل وظيفة واحدة مع اختبار عدم انحدار. لا حذف للفرع الرئيسي أو التطبيق الحالي. لا إصدارين ولا محرك مشترك بين مشروعين.
## 9. الحالة والحدود
CI 46037832000: مكتبات EasyTier للمعماريات الثلاث نجحت، 14/17 اختبارات Android نجحت، 3 فشلت. السبب المبلغ من Rust الآن permission_denied لكل المثيلات المتعثرة. لا نعرف بعد الاستدعاء المسؤول بصورة مؤكدة. مصدر EasyTier يفعّل BindDev::Auto في بناء المقابس ويصل إلى SO_BINDTODEVICE على Android حتى إذا لم يطلب مستمع UDP ربط جهاز صريحاً. التعديل المحدد للمحرك يمنع الربط الآلي باسم واجهة الجهاز على Android مع بقاء ربط عنوان المصدر وأخطاء الطلب الصريح. هذه فرضية إصلاح قابلة للاختبار، لا دليل نهائي على حل الخطأ. ربط النقل بشبكة Android معتمدة عبر Network.bindSocket/NDK المناسب وVPN protect ومنع التسرب ما زالت بوابة إلزامية قبل الإنتاج. لا استعمال لصلاحيات root، ولا تخفيف اختبار. يجب عدم توزيع APK قبل تحقق الشبكات المحلية وحصر مساراتها.
