# Wi-Call Activation Server — قرار معماري V5

التطبيق الحالي مستقل بالكامل، APK واحد بمعرف com.mokasas.wikall، ولا يوجد تطبيق مستخدم ثانٍ أو محرك مشترك بين تطبيقين. يعمل التصميم دون root، باستخدام VpnService ومقابس ضمن مساحة المستخدم فقط. لا تستخدم صلاحيات ADB في المنتج. التكامل المحلي مع سيرفرات موثوقة عبر بروتوكولات ذات إصدارات ومصادقة وتفويض؛ نقل الإنترنت يبقى معطلاً.

## فصل المكونات تدريجياً
- مجال التفعيل والعضوية مستقل عن تشغيل الشبكة والمكالمات.
- منافذ ومحولات داخل التطبيق: OverlayEngine منفذ داخلي، EasyTierEngine محوله الفعلي، WikallVpnService مستهلك للمنفذ. هذه بداية الفصل لا إنجاز جميع الطبقات.
- Network orchestration, activation, communication, directory, storage, UI and integration gateway: مسؤوليات منفصلة؛ تُنقل وظائف ConnectionController بالتدريج مع اختبارات عدم الانحدار.
- أي محول مستقبلي يطبق عقد التشغيل والتوقف والحالة والتحقق الحقيقي. لا يُربط منتج المستخدم المستقبلي بكود التطبيق.
- لا تُنشأ مكونات فارغة أو ميزات شكلية. عقود بروتوكول مرقمة، ترحيلات قاعدة بيانات واختبارات تكامل قبل كل دمج.

## بوابة الإصلاح الحالية
سجل 46031521322: 13/16 اختبارات Android نجحت، 3 فشلت، وبيانات مثيلات DHCP والترحيل كانت missing. المصدر الأصلي يسقط المثيل من نتيجة collect_network_infos إذا فشل get_running_info حتى لو سجلته FFI. هذا عيب تشخيص مؤكد، وليس إثباتاً لسبب الفشل التشغيلي.
- تعديلات Rust محددة المصدر: إرجاع حالة تشخيص مختصرة للمثيل عند عدم توفر استعلامات الحالة، مع تمييز توقف المحرك عن انتظار RPC.
- تجنب RPC خاص ببوابة VPN غير مهيأة وقراءة اسم الجهاز من الإعداد مباشرة بدلاً من RPC كامل. لا يدّعي ذلك نجاح إنشاء TUN.
- تحرير سلاسل C المملوكة في JNI بعد النسخ.
- تثبيت المصدر v2.6.4 والـcommit الأصلي، تطبيق manifest محلي بمطابقة دقيقة؛ يبقى فشل الاختبارات مانعاً للدمج. يجب مراعاة LGPL ونشر المصدر والتعديلات وفق شروط الترخيص عند التوزيع.
- اختبارات DHCP وVPN والترحيل الأصلية لا تتغير. يُختبر عدم تفسير بيانات التشخيص الناقصة كشبكة سليمة.
- لا تعتبر هذه التعديلات نجاحاً نهائياً قبل CI جديد، ولا تثبت الربط الميداني دون أجهزة غير مروّتة.
